TCP / UDP carrier

Minimal encrypted tunnels. Outer link is raw TCP or UDP. Inner frames are length-prefixed (TCP) or one datagram per frame (UDP), sealed with AES-256-GCM from SHA256(enc-key). Shared session logic lives in carrier/core (OpenTCP/OpenUDP, Data, Close, DNS, reverse).

Example JSON (forward)

{
  "server": [
    { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" },
    {
      "type": "tcp",
      "listen": "0.0.0.0:4443",
      "tag": "tcp-public",
      "target": "exit",
      "enc-key": "change-me-please"
    }
  ],
  "client": [
    {
      "type": "tcp",
      "listen": "127.0.0.1:1080",
      "address": "203.0.113.10:4443",
      "enc-key": "change-me-please",
      "tag": "tcp-fwd"
    }
  ]
}

UDP outer (same fields, type: "udp"):

{
  "server": [
    { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" },
    {
      "type": "udp",
      "listen": "0.0.0.0:4444",
      "target": "exit",
      "enc-key": "change-me-please"
    }
  ],
  "client": [
    {
      "type": "udp",
      "listen": "127.0.0.1:1080",
      "address": "203.0.113.10:4444",
      "enc-key": "change-me-please"
    }
  ]
}

Server fields

  • type — tcp or udp
  • listen — outer bind
  • target — service tag to pipe (socks/http/external)
  • enc-key — shared secret
  • tag — optional

Client fields

  • type — must match server (tcp / udp)
  • listen — local TCP+UDP bind (forward; apps speak SOCKS to the remote target) or remote publish address (reverse)
  • address — server host:port
  • enc-key — same secret
  • reverse-tag — optional; local service to expose on the server

Notes

  • No padding or jitter by default (hooks exist for later carriers).
  • Forward mode matches obfs: raw local listen; SOCKS is answered by the server target service.
  • Handshake: encrypted Hello / HelloOK bound to enc-key.
