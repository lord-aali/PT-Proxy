socks

A SOCKS5 proxy this process listens for. Use it as a tunnel target (exit on the server) or as a reverse-tag (proxy on the client, published on the far side).

Use cases

  • Forward exit: tunnel server target → this tag; apps on the client speak SOCKS5 to the tunnel client’s listen.
  • Reverse publish: this block in the client’s server list; tunnel client reverse-tag names it; peers speak SOCKS5 to the port bound on the tunnel server.

Example JSON

{
  "server": [
    {
      "type": "socks",
      "listen": "127.0.0.1:0",
      "tag": "exit"
    }
  ]
}

With auth:

{
  "server": [
    {
      "type": "socks",
      "listen": "127.0.0.1:1080",
      "tag": "exit",
      "user": "alice",
      "pass": "secret"
    }
  ]
}

Fields

FieldRequired?DefaultMeaning / when required
typeRequired—Must be socks.
listenOptional127.0.0.1:0TCP+UDP bind. Port 0 = OS assigns a free port (shown in logs / default tag).
tagOptionalsocks- + real portName used by tunnel target / reverse-tag.
user / passOptionalempty = no authIf either is set, SOCKS username/password auth is enabled. Leave both empty for open SOCKS (typical on loopback).

Capabilities

  • SOCKS5 CONNECT (TCP)
  • UDP ASSOCIATE on the same port as TCP

Applications speak SOCKS5 to whatever address reaches this daemon (often the tunnel client’s listen in forward mode, or the reverse bind on the tunnel server).
