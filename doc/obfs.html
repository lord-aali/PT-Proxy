obfs2, obfs3, obfs4

Obfuscated TCP transports (the same family Tor uses as pluggable transports). Traffic looks like random bytes after a handshake. obfs4 uses a cert/key pair; IAT mode is always 0.

Capabilities

  • Forward and reverse pipes (TCP + UDP inside a mux session)
  • A raw TCP splice to target for clients that do not mux (including Tor to an ORPort behind external)
  • obfs4 identity persisted in config.json (or printed with -gencert)

Config

Server: listen (default 0.0.0.0:3334), optional target, obfs4 cert and private-key (created on first run if empty).

Client: address host:port, obfs4 cert, listen (local in forward, published on the server in reverse), optional reverse-tag.

How it works

Server accepts TCP, completes the obfs handshake, then either starts a mux session (PTPXMUX1 + smux) or splices raw TCP to target. Client dials with cert and iat-mode=0, then muxes: local TCP+UDP listen in forward, or a reverse bind request plus dials to the tagged service. Sessions reconnect if the link drops; the local listen stays up in forward mode.

obfs4 cert is base64 of node ID + ntor public key (padding stripped). Private key is hex. A new length-obfuscation seed is drawn each start.
