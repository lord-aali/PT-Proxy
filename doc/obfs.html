obfs2, obfs3, obfs4

Obfuscated TCP transports. After the handshake, traffic looks like random bytes. Carries TCP and UDP (framed). Supports forward pipes to a tagged service and reverse binds on the same listener. obfs4 can also splice a raw TCP client (for example Tor) to an external target.

Use cases

  • Forward: apps on the client reach a socks / http / external service on the server through an obfuscated link.
  • Reverse: publish a port on the server that reaches a service listed in the client’s server array.
  • Both on one listen: set target for forward clients; reverse clients still work on the same port.
  • Tor ORPort: target points at an external ORPort; non-mux TCP is spliced there.

Example JSON (forward + reverse on one server)

{
  "server": [
    { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" },
    {
      "type": "obfs4",
      "listen": "0.0.0.0:3334",
      "tag": "obfs-public",
      "target": "exit",
      "cert": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAABBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB",
      "private-key": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    }
  ],
  "client": [
    {
      "type": "obfs4",
      "listen": "127.0.0.1:1080",
      "address": "203.0.113.10:3334",
      "cert": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAABBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB",

}

Reverse client (same server listen; service lives in this process’s server list):

{
  "server": [
    { "type": "external", "listen": "127.0.0.1:22", "tag": "ssh" }
  ],
  "client": [
    {
      "type": "obfs4",
      "listen": "0.0.0.0:2222",

}

Server fields

FieldRequired?DefaultMeaning / when required
typeRequired—obfs2, obfs3, or obfs4.
listenRequired in practice(must be a bindable host:port)Public TCP bind for the tunnel. Common value: 0.0.0.0:3334.
tagOptionaltype-port after bindName in logs. Port 0 uses the assigned port in the default tag.
targetOptionalempty (reverse-only hub)Service tag for forward streams. Reverse binds are always allowed. Omit for reverse-only.
certobfs4: required to keep identity (or auto-filled)generated on first run if emptyobfs4 only. Client must use the same value. Use -gencert to print a pair. Ignored for obfs2/obfs3.
private-keyRequired with cert for obfs4generated with certobfs4 only. Hex private key matching cert. Do not put this on the client.

IAT mode is fixed to 0 (not a JSON field).

How it works

Server accepts TCP, completes the obfs handshake, then either starts a mux session (PTPXMUX1 + smux) or splices raw TCP to target. Client dials with cert (obfs4) and muxes: local TCP+UDP listen in forward, or a reverse bind plus dials to the tagged service. Sessions reconnect if the link drops; the local listen stays up in forward mode.
