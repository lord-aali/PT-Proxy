DPI (HTTP/HTTPS tunnel)

Carries TCP and UDP inside encrypted HTTP(S) so the session looks like ordinary web traffic. Supports domain fronting, CDN-friendly short POSTs, or a long stream uplink. Forward and reverse on the same server.

Use cases

  • Networks that allow HTTPS to a specific hostname (or a CDN) but block raw TCP obfuscation.
  • Forward exit via target to socks/http/external on the server.
  • Reverse: publish a port on the DPI server that reaches a service on the client.

Example JSON (HTTPS server + forward client)

{
  "server": [
    { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" },
    {
      "type": "dpi",
      "tag": "dpi-public",
      "target": "exit",
      "http": "0.0.0.0:80",
      "https": "0.0.0.0:443",
      "enc-key": "change-me-shared-key",
      "protocol": "auto",
      "self-signed": true,
      "tls-cert": "/etc/ssl/certs/server.crt",
      "tls-key": "/etc/ssl/private/server.key",
      "acme-email": "admin@example.com",
      "acme-domain": "proxy.example.com",
      "cert-dir": "/var/lib/ptproxy/certs",
      "redirect": "https://example.com/",
      "serve-dir": "/var/www/html",
      "backend": "http://127.0.0.1:8080"
    }
  ],
  "client": [
    {
      "type": "dpi",
      "listen": "127.0.0.1:1080",
      "address": "https://203.0.113.10:443",
      "enc-key": "change-me-shared-key",
      "protocol": "auto",
      "sni": "proxy.example.com",
      "front-host": "allowed.example.com",
      "insecure": true,
      "redirect-follow": true,
      "uplink": "post-async",
      "verbose": false,
      "tag": "dpi-fwd"
    }
  ]
}

Domain fronting (dial IP in URL, TLS/name for the allowed host):

{
  "client": [
    {
      "type": "dpi",
      "listen": "127.0.0.1:1080",
      "address": "https://203.0.113.10:443",
      "enc-key": "change-me-shared-key",
      "sni": "allowed.example",
      "front-host": "allowed.example",
      "uplink": "post-async"
    }
  ]
}

Reverse client (forces uplink to stream):

{
  "server": [
    { "type": "external", "listen": "127.0.0.1:22", "tag": "ssh" }
  ],
  "client": [
    {
      "type": "dpi",
      "listen": "0.0.0.0:2222",
      "address": "https://203.0.113.10:443",
      "enc-key": "change-me-shared-key",
      "reverse-tag": "ssh",
      "insecure": true
    }
  ]
}

Server fields

FieldRequired?DefaultMeaning / when required
typeRequired—Must be dpi.
httpAt least one of http / httpsemptyPlain HTTP listen (e.g. 0.0.0.0:80). Server refuses to start if both are empty.
httpsAt least one of http / httpsemptyHTTPS listen (e.g. 0.0.0.0:443). Default tag uses this port when set.
enc-keyOptional (use a real secret)default-encryption-key-change-meShared with the client. Encrypts tunnel payloads.
protocolOptionalautoWire protocol selection hint.
targetOptionalemptyService tag for forward connects. Reverse binds still work when set.
tagOptionaldpi- + https or http portLog label.
self-signedOptionalfalseIf https is set and you have no files/ACME, set true so the server generates a cert.
tls-cert / tls-keyConditionalemptyRequired for HTTPS when not using self-signed and not using ACME.
acme-email / acme-domainConditionalemptyLet’s Encrypt path for HTTPS instead of files or self-signed.
cert-dirOptionalemptyWhere ACME/self-signed material is stored when used.
redirectOptionalemptyURL to redirect non-tunnel requests to. Takes priority over backend and serve-dir.
serve-dirOptionalemptyLocal filesystem path to serve as a static site. index.html is the default document; directory listing is shown when absent.
backendOptionalemptyURL of an existing HTTP server to reverse-proxy non-tunnel requests to (e.g. http://127.0.0.1:80). Takes priority over serve-dir. Supports Apache .htaccess, PHP, CGI via the upstream server.

HTTPS requires exactly one TLS path: self-signed, or tls-cert+tls-key, or acme-email+acme-domain.

Wire summary

Flows use a connID. Messages: Connect, Data, Close, UDP, ReverseBind, ReverseOpen. Paths such as /.well-known/cdn-cache/, /api/v2/upload, /api/v2/stream, and /download/session/ carry the tunnel.
