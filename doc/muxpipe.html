Multiplexing

Several TCP connections and a UDP flow share one camouflage session. Package common/muxpipe, using smux v2 (10-minute keepalive).

What it can do

  • Many concurrent TCP pipes
  • UDP datagrams with peer addresses
  • Ask the far side to bind a host:port (reverse) and accept connections back

Obfs

After the obfuscated handshake, a PT Proxy client writes PTPXMUX1 and starts smux. The server waits up to 500ms:

  • Prefix present → mux session: forward streams dial target when set; reverse binds are always accepted.
  • Otherwise, if target is set → raw TCP splice to that address (fits Tor ORPort and other single-stream TCP). If target is unset, the connection ends.

Stream kinds

First byte of each smux stream:

ValueNameCapability
1KindTCPBidirectional TCP. Server dials target (dropped if target empty).
2KindUDPDatagrams: 1-byte addr length, addr, 2-byte payload length, payload. Needs target.
3KindRevBindListen address in; bound address out; then the server accepts. Allowed even when target is set.
4KindRevTCPIncoming reverse TCP. Client dials reverse-tag.

Snowflake

KCP already provides smux. The same kind bytes run on that session; there is no extra prefix.
