FTP tunnel

An FTP/FTPS control connection plus persistent PASV data sockets. Control looks like FTP; data files look like website assets. Encrypted frame batches ride STOR/RETR.

Capabilities

  • Forward and reverse (TCP + UDP)
  • Plain FTP or FTPS (TLS on control and data)
  • Several parallel upload and download channels
  • Optional decoy LIST/RETR cover traffic
  • PASV IP and port ranges for NAT; optional override addresses on the client

Config

Server: listen (default 0.0.0.0:21), user / pass, enc-key, pasv-ip, upload-ports / download-ports, optional TLS files, optional target.

Client: address FTP host:port, same credentials and key, listen, channel counts, optional PASV overrides, decoy, reverse-tag.

How it works

Login, PASV, then long-lived data connections named with a session token. Frames: ConnID, type, seq, data; batches sealed with AES-256-GCM (key = SHA-256 of the passphrase).
