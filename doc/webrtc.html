WebRTC carrier

Outer transport is a normal WebRTC data channel: ICE, DTLS, and SCTP, built with Pion. Signaling is a small HTTP POST of the SDP offer. Each data-channel message is one encrypted carrier/core frame. Forward and reverse match the other carriers.

Example JSON (forward)

{
  "server": [
    { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" },
    {
      "type": "webrtc",
      "listen": "0.0.0.0:8443",
      "tag": "webrtc-public",
      "target": "exit",
      "enc-key": "change-me-please",
      "stun": "stun:stun.l.google.com:19302",
      "public-ip": "203.0.113.10"
    }
  ],
  "client": [
    {
      "type": "webrtc",
      "listen": "127.0.0.1:1080",
      "address": "http://203.0.113.10:8443/webrtc",
      "enc-key": "change-me-please",
      "stun": "stun:stun.l.google.com:19302",
      "tag": "webrtc-fwd"
    }
  ]
}

Server fields

  • listen — HTTP signaling bind. Default 0.0.0.0:8443. Path is /webrtc.
  • target — service tag for forward flows
  • enc-key — encrypts frames inside the data channel
  • stun — optional STUN URL. Empty uses host candidates only (fine on a public IP or localhost).
  • public-ip — optional 1:1 NAT address advertised as a host candidate
  • redirect — optional URL. Browser requests (anything except POST /webrtc) redirect here. Takes priority over backend and serve-dir.
  • backend — optional URL. Every path except /webrtc is reverse-proxied here and the request path is kept, so /blog fetches https://example.com/blog. A domain name is sent as the Host header and, for HTTPS, as the TLS server name. An IP backend keeps the incoming Host header.
  • serve-dir — optional directory to serve as a static site. index.html is the default document.
  • pad-max / jitter-ms — optional shaping

Client fields

  • address — signaling URL (http://host:8443 or http://host:8443/webrtc)
  • listen — local TCP+UDP bind (forward) or remote publish address (reverse)
  • enc-key — must match the server
  • stun — optional, same idea as the server
  • reverse-tag — optional

Notes

  • ICE uses UDP. Allow the signaling TCP port and UDP for the ICE candidates.
  • No root requirement. This is not a raw socket.
  • The data channel label is ptproxy. DTLS and ICE are genuine WebRTC.
  • GET / is a cover page. With no redirect, backend, or serve-dir it returns a short HTML page instead of 404. /webrtc stays the signaling path and is not forwarded to backend.
