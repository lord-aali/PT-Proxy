Snowflake

A WebSocket relay with TurboTunnel, KCP, and smux. The session looks like a website WebSocket. Optional WSS. Optional domain fronting via sni and front-host. Optional upstream proxy to reach the WebSocket.

Capabilities

  • Forward and reverse (TCP + UDP over smux)
  • ws:// and wss://
  • Custom TLS SNI and Host header

Config

Server: listen (default 0.0.0.0:8080), optional tls-cert / tls-key, optional target.

Client: address WebSocket URL, listen, optional sni, front-host, proxy, insecure, reverse-tag.

How it works

HTTP upgrades to WebSocket. A token and client ID select a packet queue. KCP runs in stream mode over those packets, then smux v2. Each smux session multiplexes TCP pipes, UDP, and reverse binds (same stream kinds as muxpipe).
