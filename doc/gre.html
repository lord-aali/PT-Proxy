GRE carrier

Outer packets are GRE (IP protocol 47) with a normal keyed header: key and sequence number, protocol type IPv4 (0x0800). The GRE payload is one encrypted carrier/core frame. Forward and reverse match the TCP/UDP carrier.

Example JSON (forward)

{
  "server": [
    { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" },
    {
      "type": "gre",
      "listen": "0.0.0.0",
      "tag": "gre-public",
      "target": "exit",
      "enc-key": "change-me-please",
      "gre-key": "1"
    }
  ],
  "client": [
    {
      "type": "gre",
      "listen": "127.0.0.1:1080",
      "address": "203.0.113.10",
      "enc-key": "change-me-please",
      "gre-key": "1",
      "tag": "gre-fwd"
    }
  ]
}

Server fields

  • listen — local IPv4 to bind the raw socket. Default 0.0.0.0. Not a TCP port.
  • target — service tag for forward flows
  • enc-key — AES-GCM secret
  • gre-key — GRE key field (decimal). Default 1. Must match the client.
  • pad-max / jitter-ms — optional shaping. 0 disables them.

Client fields

  • address — peer IPv4 (host or host:port; the port is ignored)
  • listen — local TCP+UDP bind (forward) or remote publish address (reverse)
  • enc-key, gre-key — must match the server
  • reverse-tag — optional

Notes

  • Prefers a raw IPv4 socket (protocol 47). If the OS denies that (typical on Windows without extra privileges), both sides switch to GRE-in-UDP on port 4754: a normal UDP datagram whose payload is still a GRE header plus one encrypted frame. Set listen or address to host:port to force that UDP port.
  • If you are a root/admin user, but you wanted to use UDP GRE-in-UDP instead of Protocol 47, just add a port to listen in server and address in client. The service will locks on UDP.
  • Each GRE datagram is one frame. Large flows fragment like any GRE tunnel.
  • Packets with a different gre-key are dropped.
