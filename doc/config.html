Config and tags

JSON with two optional arrays: server and client. Path is -c (default ./config.json). Working directory is -d.

{
  "server": [ { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" } ],
  "client": [ { "type": "obfs4", "listen": "127.0.0.1:1080", "address": "1.2.3.4:3334", "cert": "..." } ]
}

Fields

FieldOnMeaning
typeevery blocksocks, http, external, obfs2/3/4, dpi, snowflake, ftp
tagevery blockName used by target and reverse-tag. If omitted: type-port after bind. Port 0 uses the assigned port. DPI uses the HTTPS port if set, else HTTP.
listenmost blocksBind address. For external, the address to dial.
targettunnel serverTag of the service to reach. Empty: this tunnel accepts reverse binds from clients.
reverse-tagtunnel clientTag of a service in this file’s server list. Set: reverse; listen is published on the tunnel server. Empty: forward; listen is local.
addresstunnel clientTunnel server (host:port or URL).

TCP and UDP share the same host:port. There is no protocol field in JSON. An http target is TCP-only.

BlockDefault

client addressobfs 127.0.0.1:3334, dpi https://127.0.0.1:443, snowflake ws://127.0.0.1:8080/, ftp 127.0.0.1:21

DPI client: uplink post-async, redirect-follow true. Reverse DPI uses uplink stream.

Startup

  1. Start socks / http / external in server, assign ports, register tags.
  2. Start tunnel servers. Unknown target tags fail that entry.
  3. Start tunnel clients. Unknown reverse-tag is logged and that client is skipped.

Log tags look like [obfs4-3334] or [socks-49152].
