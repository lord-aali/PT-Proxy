external

A name for a process that already listens somewhere. listen is the address to dial (SSH, a game, DNS, Tor ORPort, …). Nothing is bound by this block.

Use cases

  • Forward: tunnel client local port ↔ this address on the server machine.
  • Reverse: this address on the client machine ↔ a port bound on the tunnel server.
  • Tor ORPort: obfs server target → this tag; raw TCP clients are spliced here.

Example JSON

{
  "server": [
    {
      "type": "external",
      "listen": "127.0.0.1:22",
      "tag": "ssh"
    }
  ]
}

UDP service (same host:port for TCP and UDP):

{
  "server": [
    {
      "type": "external",
      "listen": "127.0.0.1:53",
      "tag": "dns"
    }
  ]
}

Fields

FieldRequired?DefaultMeaning / when required
typeRequired—Must be external.
listenRequirednoneDial address of the backend (host:port). The process refuses to start this block if empty.
tagOptionalexternal- + port from listenName for tunnel target / reverse-tag.

Capabilities

  • TCP streams to that host:port
  • UDP datagrams to the same host:port

A TCP-only backend simply never sees UDP; a UDP-only backend never accepts TCP.
