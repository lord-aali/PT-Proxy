Custom WG carrier

Outer transport is UDP. Each datagram is one ChaCha20-Poly1305 blob carrying an encrypted carrier/core frame. The header is a 16-byte marker, class, direction, and counter. It is not a WireGuard handshake, mac1, mac2, or transport header, and it does not speak to WireGuard peers. Forward and reverse match the other carriers.

Example JSON (forward)

{
  "server": [
    { "type": "socks", "listen": "127.0.0.1:0", "tag": "exit" },
    {
      "type": "cwg",
      "listen": "0.0.0.0:4446",
      "tag": "cwg-public",
      "target": "exit",
      "enc-key": "change-me-please"
    }
  ],
  "client": [
    {
      "type": "cwg",
      "listen": "127.0.0.1:1080",
      "address": "203.0.113.10:4446",
      "enc-key": "change-me-please",
      "tag": "cwg-fwd"
    }
  ]
}

Server fields

  • listen — UDP bind. Default 0.0.0.0:4446.
  • target — service tag for forward flows
  • enc-key — hashed to the ChaCha20-Poly1305 key
  • pad-max / jitter-ms — optional shaping

Client fields

  • address — server host:port
  • listen — local TCP+UDP bind (forward) or remote publish address (reverse)
  • enc-key — must match the server
  • reverse-tag — optional

Notes

  • Allow UDP on the listen port. There is no TCP port and no root requirement.
  • Packets are kept off WireGuard's fixed sizes (64, 92, and 148 bytes) and off 16-byte alignment.
  • A 64-packet window accepts reordered datagrams. Older duplicates are dropped.
